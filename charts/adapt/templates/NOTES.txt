A superuser is being bootstrapped via a post-install/post-upgrade hook Job
({{ include "adapt.fullname" . }}-bootstrap-admin). It is retained after

  kubectl get job {{ include "adapt.fullname" . }}-bootstrap-admin -n {{ .Release.Namespace }}

{{- if not .Values.bootstrapAdmin.existingSecret }}

Username: {{ .Values.bootstrapAdmin.username }}
Retrieve the generated password with:

  kubectl get secret {{ include "adapt.fullname" . }}-bootstrap-admin -n {{ .Release.Namespace }} -o jsonpath='{.data.password}' | base64 -d && echo
{{- else }}

Credentials were sourced from the existing secret
{{ .Values.bootstrapAdmin.existingSecret }} you provided.
{{- end }}

Note: if you uninstall and reinstall against the same persisted data (an
existing PVC), the admin user created by the first install keeps its
original password — the newly generated secret value won't apply, since
addsuperuser is a no-op for a username that already exists. Use
bootstrapAdmin.existingSecret with a known password if you need that
guarantee, or reset the password via `adapt admin change-password`.
{{- else }}

Superuser bootstrapping is disabled (bootstrapAdmin.enabled=false). Create
one manually with:

  kubectl exec -it -n {{ .Release.Namespace }} deploy/{{ include "adapt.fullname" . }} -- \
    adapt addsuperuser {{ .Values.persistence.mountPath | default .Values.adapt.rootPath }} --username admin

The -it flag is required because addsuperuser prompts for the password.
For scripts, use --password, --password-confirm, and --allow-weak-password
as applicable.
{{- end }}

Documents can be copied into the document root with:

  kubectl cp ./documents/. {{ .Release.Namespace }}/$(kubectl get pod -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }},app.kubernetes.io/component=server -o jsonpath='{.items[0].metadata.name}'):/{{ trimPrefix "/" (.Values.persistence.mountPath | default .Values.adapt.rootPath) }}

For repeatable or shared content, configure `extraVolumes` and
`extraVolumeMounts` to mount a ConfigMap below the writable document root,
such as `/data/documents`, or mount a writable NFS/share volume at `/data`
with `externalDocumentRoot=true`. Do not mount a ConfigMap at `/data`.

{{- if .Values.externalDocumentRoot }}
The document root is provided by the volume(s) configured in extraVolumes /
extraVolumeMounts. This chart does not manage that volume's durability or
writability — verify it independently.
{{- else if not .Values.persistence.enabled }}
WARNING: persistence.enabled=false uses an emptyDir document root. All
documents and accounts are lost when the pod restarts. Enable persistence for
anything you need to keep.
{{- end }}
